#+TITLE: spngbench — SPNG vs OSP compute-performance benchmark

Compare the compute performance of the SPNG and OSP signal-processing chains for
the PDHD detector, across CPU-core and GPU allowances.  Designed to be re-run and
extended (more inputs/events, more cores/GPUs, other detectors later).

* What it does

The =spngdir= workflow runs a single "kitchen sink" wire-cell job.  This
benchmark *factors* it into three separate jobs (=stage= TLA / driver stage):

- ~stage=sim~  : =depos -> drift -> detsim=  -> ADC frame file(s)
- ~stage=osp~  : ADC frame file(s) -> OSP    -> signal frame file(s)
- ~stage=spng~ : ADC frame file(s) -> SPNG   -> signal frame file(s)

The sim job is run *once* per depo input; its ADC frame file feeds *both* the
OSP and SPNG jobs, so they process identical input and the shared simulation
cost is excluded from the SP timing.  Later the ADC file may be replaced by one
made from real detector data to compare against.  The factored pieces come from
=spng/det.jsonnet= (=depos_to_adc=, =osp=, =spng=).

Two files:
- =spngbench.jsonnet= — the factored wire-cell config (TLAs: =input=, =model_file=,
  =output=, =which=, =detname=, =device=, =engine=, =wc_cores=).
- =spngbench.py= — the driver (single runs, grid scan, log analysis, rollups).

* Timing

Each wire-cell log is harvested two ways:

1. *Phase intervals* from log timestamps: =startup=, =config=, =first_execute=,
   =execution=, =last_execute=, =finalize= (robust to spdlog reordering and
   continuation lines; engine-agnostic markers).
2. *Per-node* wall/core seconds from the "Timer:" lines (Pgrapher) or the
   =TbbDataFlowGraph= "calls=..." summary (TbbFlow).  Rolled up per node as
   mean±stdev over repeats/inputs, plus category sums:
   - =forward=  — the DNN forward (OSP =Pytorch::DNNROIFinding=, SPNG
     =SPNG::TensorForward=),
   - =sp_other= — all other SP nodes (OSP =OmnibusSigProc=, other =SPNG::*=),
   - =sp_total= = forward + sp_other, =all_total= from the timer total.

** Thread control (important)

- *Wire-cell* node parallelism is set by =wc_cores= → =TbbDataFlowGraph.max_threads=.
- *Torch* intra-op threads are set by the =OMP_NUM_THREADS= environment variable
  (the driver sets it per run); it maps to torch's =at::get_num_threads=.

These are independent axes. 

* Usage

#+begin_src sh
# one chain at one config
python3 spngbench.py run spng --device cpu --wc-cores 1 --torch-cores 1

# both chains at one config, with the OSP/SPNG comparison JSON
python3 spngbench.py pair --device cpu --wc-cores 2 --torch-cores 4

# re-analyze an existing wire-cell log
python3 spngbench.py analyze some-wire-cell.log

# grid scan (CPU): wc {1,2,3,4} x torch {1,2,4,8,16,32}, skipping wc*torch>64
python3 spngbench.py grid --mode cpu --which both

# subset the grid
python3 spngbench.py grid --mode cpu --which spng --wc-cores 1 2 --torch-cores 1 4

# single-GPU grid (device=gpu, torch=1, wc {1,2,3,4}); OOM is recorded, not fatal
python3 spngbench.py grid --mode gpu --which both

# multi-GPU sharded grid (transverse/longitudinal x ngpu x wc); cells needing
# more GPUs than present are recorded as skipped
python3 spngbench.py grid --mode shard --which both

# a single sharded SPNG run
python3 spngbench.py run spng --device gpu0 --gpu-scheme transverse --ngpu 2

# everything (cpu + gpu + shard), from a config file
python3 spngbench.py grid --mode all --config spngbench.json

# see the effective configuration
python3 spngbench.py show-config --config spngbench.json

# human-readable summary (Markdown + HTML + LaTeX) from a compare/report/grid JSON
python3 spngbench.py report spngbench-pdhd/compare-cpu-wc1-omp1.json -o report-dir

# cross-grid summary spanning every grid point in a grid-index.json
python3 spngbench.py grid-report spngbench-pdhd/grid-index.json -o grid-report-dir
#+end_src

Default input is =toolkit/test/data/muon-depos.npz=; override with =--input= (repeatable)
or the config file's =inputs=.

* Outputs

Into =--outdir= (default =spngbench-pdhd/=):
- =report-<which>-<device>-wc<N>-omp<M>.json= — per-config rollup (schema
  =spngbench-config/1=): meta, phase durations, raw nodes, per-node stats,
  category sums.
- =compare-<device>-wc<N>-omp<M>.json= — combined OSP+SPNG (=spngbench-compare/1=).
- =grid-index.json= — one row per grid cell (=spngbench-grid/1=), updated
  incrementally so partial runs survive.

Outcomes: =ok=, =oom= (GPU out-of-memory, marked and skipped), =error=, =skipped=.

* Summary report

=report= reads a =compare-*.json= (or a per-config report, or a grid index) and
writes a directory with =summary.{md,html,tex}= sharing the same PNG figures.
It surfaces OSP-vs-SPNG and per-node differences, separating I/O from SP nodes
and, within SP, the DNN forward (=Pytorch::DNNROIFinding= / =SPNG::TensorForward=)
from the non-DNN algorithms.  Figures: category-composition bars (OSP vs SPNG),
per-stage top-node bars, and the OSP and SPNG *flow graphs* (GraphViz =dot=)
with each node annotated by wall/core time and colored by category.  The LaTeX
builds with =pdflatex= (needs =graphicx=, =booktabs=); the flow graphs need the
=dot= and =wcpy= programs (skipped with =--no-graphs= or if absent).

* Grid report

=grid-report= consumes a =grid-index.json= and writes a cross-grid summary that
spans every grid point.  It contains:

- OSP and SPNG *matrices* (same axes): columns = wire-cell cores, rows = the
  compute config (torch cores for CPU cells, GPU-device/scheme for GPU cells).
  Each cell is a grid point drawn as 2×2 *sub-pixels* --- DNN (top-left),
  sp\_other (top-right), other (bottom-left), total (bottom-right) --- on a
  single shared time colour scale (one colour bar).  Not-tested cells are black,
  crashed cells white.
- Trend *bar charts* (total wall per point; SPNG/OSP ratio per point).
- A grid *overview table*.
- A *per-grid-point summary* for every cell (=report= output), linked from the
  Markdown/HTML and =\input= into the LaTeX, with a table of contents.

Per-point flow graphs are off by default for speed; enable with =--point-graphs=.

* Config file

JSON is always supported; YAML if =pyyaml= is installed.  A committed
=spngbench.json= mirrors the built-in defaults — copy and edit it.  CLI flags
override the file.  Keys: =detname=, =model_file=, =inputs=, =outdir=, =repeats=,
=which=, =engine=, =hw.max_hyperthreads=, =cpu_grid.{wc_cores,torch_cores}=,
=gpu_grid.{device,wc_cores,torch_cores}=, =two_gpu.{wc_cores,devices}=.

* Extending

- *More inputs/events*: set =inputs= to a list; per-node stats become mean±stdev.
- *More cores*: bump =cpu_grid= ranges and =hw.max_hyperthreads=.
- *More GPUs*: the SPNG graph is sharded by a device MATRIX (=gpu_scheme=, =ngpu=),
  applied by rewriting =data.device= on per-APA SPNG node configs (names start
  "tpc<N>"), so it extends to any GPU count:
  - =transverse= : device = gpu[ tpc_index % ngpu ].  All nodes of one APA share
    a GPU; APA pipelines are independent so with one event in flight only one
    runs at a time and the GPU never OOMs.  Up to (#APA) GPUs (4 for PDHD).
  - =longitudinal= : device = gpu[ stage_index % ngpu ], stages (decon/filter/
    dnn/roi) matched by node-name keyword; tensors cross GPUs at stage
    boundaries.  Extend the =stages= list in =spngbench.jsonnet= for finer control.
  OSP (a single DNN) is not sharded and uses the base =device=.  Cells needing
  more GPUs than present are recorded as skipped.
- *Other detectors* (DUNE FD): set =detname= once SPNG detconf exists for it.
  Multi-APA detectors automatically get per-TPC ADC frame files (=-tpc<N>= suffix)
  and enable the transverse scheme across their APAs.

* Diagnostics

=spng/test/check_threads.cxx= is a standalone torch+TBB toy (CLI-driven) used to
root-cause thread-control and core-time behavior.  Build target
=WireCellSpng__check_threads=.
